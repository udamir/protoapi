# ProtoApi 0.1

This page defines version 0.1 of the ProtoApi document format: the objects of a document, how protobuf constructs map to them, the canonical form of every value, and what producers and printers of documents must do. The [overview](/spec/) introduces the format, and the [conversion examples](/examples/) show it for every feature.

## 1. Introduction

A ProtoApi document describes a set of `.proto` files — proto2, proto3 or editions 2023, 2024 and 2026 — as one JSON value. It is designed to be diffed, rendered and printed back: two builds of the same files give equal documents, whatever the producer, and printing a document gives `.proto` files that build to the same document.

A document is produced from `.proto` text or from a `FileDescriptorSet`. Both producers of the reference implementation give byte-identical documents for the same input.

## 2. Conventions

The key words "MUST", "MUST NOT", "SHOULD" and "MAY" are to be interpreted as described in [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119).

- **Document**: a JSON value conforming to this specification. Documents are shown as YAML here; YAML and JSON documents are equivalent.
- **Element**: a file, service, method, message, field, oneof, enum, enum value or extension.
- **Fully qualified name** (fqn): the package and the enclosing message names joined by dots, without the leading dot of protobuf's notation: `shop.v1.Pet.Dog`.
- **Position**: a place where a type is written — a field, the `items` of a repeated field, the `propertyNames` (key) and `additionalProperties` (value) of a map field.
- **Bundled file**: a file the producer resolved from its built-in definitions (or an equivalent set supplied as a bundle) rather than from the user's input.
- **Absent**: a key that is not present. No key of a document is ever `null`.

## 3. Format

### 3.1 Document structure

```yaml
protoapi: "0.1"
files: # one entry per source file, keyed by import path
  <path>: File
services: # keyed by fully qualified service name
  <pkg.Service>: Service
components:
  messages: { <pkg.Message>: Message } # nested messages as pkg.Outer.Inner
  enums: { <pkg.Enum>: Enum }
  extensions: { <pkg.scope.name>: Extension }
```

`protoapi` is REQUIRED and is the string `"0.1"`. `files`, `services` and `components` (and each of its three maps) are present only when not empty; a producer MAY omit `files` (and every `file` key) on request.

### 3.2 Objects

#### Element

Every element MAY carry these keys:

| Key | Type | Description |
| --- | --- | --- |
| `title` | string | On services, messages, enums and extensions: the short name (`Inner` for `pkg.Outer.Inner`). On methods, fields, values and oneofs (keyed by their short name already): only from an explicit `@Title` tag or an openapiv2 `title`. |
| `file` | string | On services, messages, enums and extensions: the import path of the declaring file. |
| `description` | string | The leading and trailing comment of the element, normalized ([§3.8](#_3-8-annotation-layer)). |
| `deprecation` | `{ reason?: string }` | The element is deprecated: `[deprecated = true]`, a `Deprecated:` first line or a `@Deprecated` tag. `reason` from the comment. |
| `options` | object | Every option of the element that is not lifted into a keyword ([§3.7](#_3-7-options)). |
| `x-annotation-conflicts` | array | Annotation sources that disagree on a keyword ([§3.8](#_3-8-annotation-layer)). |

#### File

| Key | Type | Description |
| --- | --- | --- |
| `description` | string | The comments above the first statement that are detached from it by a blank line (the file header). Absent on bundled files. |
| `syntax` | string | `proto2`, `proto3`, `2023`, `2024`, `2026`, or an unknown edition verbatim. Absent only when a syntax error precedes the first complete statement. |
| `package` | string | The package. |
| `imports` | string[] | Import paths as written, in source order. |
| `importFlags` | object | Import path → `public`, `weak` or `option`, for imports with a modifier. |
| `options` | object | File options not lifted (`go_package`, `java_package`, `features`, custom options, `deprecated`). |
| `bundled` | `true` | The file was resolved from the bundle and is not an entry file. |

#### Service

An element with `methods`: method name → Method, in declaration order.

#### Method

| Key | Type | Description |
| --- | --- | --- |
| `request`, `response` | `{ schema: { $ref }, stream?: true }` | The message type, a reference to `#/components/messages/<fqn>`; `stream: true` for a streaming request or response. |
| `idempotency` | `NO_SIDE_EFFECTS` \| `IDEMPOTENT` | From `idempotency_level`; `IDEMPOTENCY_UNKNOWN` is not written. |
| `http` | HTTP rule | From `(google.api.http)`. |

An **HTTP rule** is `{ method, path, body?, responseBody?, additionalBindings? }`: `method` is `GET`, `PUT`, `POST`, `DELETE`, `PATCH`, or the `kind` of a `custom` pattern; `additionalBindings` is an array of HTTP rules.

#### Message

| Key | Type | Description |
| --- | --- | --- |
| `type` | `"object"` | REQUIRED. |
| `properties` | object | REQUIRED: field name → Field, in declaration order (`{}` for a message without fields). |
| `oneofs` | object | Oneof name → Element, for real oneofs (not the synthetic oneofs of proto3 `optional`). |
| `reserved` | Reserved | `{ numbers?: [start, end][], names?: string[] }`. |
| `extensions` | `[start, end][]` | The extension ranges; `max` is 536870911. |
| `extensionOptions` | array | `{ range: [start, end], options }` for each declared extension range with options other than `declaration`. |
| `jsonFormat` | string | The resolved `features.json_format` when it is not `ALLOW`. |

#### Field

A field is an element with a `number` (REQUIRED) and exactly one type shape:

| Shape | Keys |
| --- | --- |
| scalar | `type` (`integer`, `number`, `boolean` or `string`) and `protoType` ([§3.4](#_3-4-scalar-mapping)) |
| message or enum | `$ref`: `#/components/messages/<fqn>` or `#/components/enums/<fqn>` |
| repeated | `type: array`, `items`: a scalar (`{ type, protoType }`) or `{ $ref }` |
| map | `type: object`, `propertyNames`: the key scalar, `additionalProperties`: the value (`{ type, protoType }` or `{ $ref }`) |

and these protobuf keywords:

| Key | Type | Description |
| --- | --- | --- |
| `presence` | `explicit` \| `required` | Field presence, rule P of [§3.5](#_3-5-identity-ordering-and-omission-rules). |
| `oneof` | string | The name of the field's oneof. |
| `jsonName` | string | An explicit `json_name` that differs from the default, rule J of [§3.5](#_3-5-identity-ordering-and-omission-rules). |
| `default` | string, number or boolean | The proto2 / editions `[default = …]`, canonical ([§3.6](#_3-6-canonical-values)). |
| `delimited` | `true` | A proto2 group, or editions `message_encoding = DELIMITED`. |
| `packed` | `false` | A packable repeated field (numeric or enum) whose resolved encoding is expanded. |
| `utf8Validation` | `false` | A `string` position whose resolved `utf8_validation` is `NONE` (on the field, or on `items`, `propertyNames`, `additionalProperties`). |

and the annotation keywords of [§3.8](#_3-8-annotation-layer): `required`, `readOnly`, `writeOnly`, `immutable`, `format`, `minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`, `multipleOf`, `minLength`, `maxLength`, `pattern`, `minItems`, `maxItems`, `uniqueItems`, `minProperties`, `maxProperties`, `enum`, `const`, `examples` and `x-default`. Value keywords of a repeated or map field are written on its `items`, `propertyNames` or `additionalProperties`.

#### Enum

| Key | Type | Description |
| --- | --- | --- |
| `type` | `"string"` | REQUIRED. |
| `values` | object | REQUIRED: value name → Enum Value, in declaration order. An alias is a second name with the same number. |
| `reserved` | Reserved | As on messages. |
| `closed` | `true` | A closed enum: proto2, or editions `enum_type = CLOSED`. |
| `jsonFormat` | string | As on messages. |

An **Enum Value** is an element with a `number` (REQUIRED).

#### Extension

A field with `extendee`, the fully qualified name of the extended message. Custom option definitions are ordinary extensions (of `google.protobuf.FieldOptions` and the other option messages).

#### Annotation Conflict

`{ keyword, kept: { source, value }, dropped: { source, value } }`, where `source` is `option`, `google.api`, `buf.validate`, `validate.rules`, `openapiv2`, `tag` or `prefix`.

### 3.3 Construct mapping

| Protobuf | ProtoApi |
| --- | --- |
| `syntax = "proto2"` / `"proto3"`, `edition = "2023"` | `files[path].syntax`: `proto2`, `proto3`, `"2023"` |
| `package a.b;` | `files[path].package`; the prefix of every component key |
| `import "x.proto";`, `import public` / `weak` / `option` | `files[path].imports`; the modifier under `importFlags` |
| file options | `files[path].options` |
| comments above `syntax` separated by a blank line | `files[path].description` |
| `service S { rpc M(Req) returns (Res); }` | `services["pkg.S"].methods.M = { request: { schema: { $ref } }, response: { schema: { $ref } } }` |
| `rpc M(stream Req) returns (stream Res)` | `request.stream: true`, `response.stream: true` |
| `option idempotency_level = NO_SIDE_EFFECTS;` | `idempotency: NO_SIDE_EFFECTS` |
| `option (google.api.http) = { get: "/v1/{id}" };` | `http: { method: GET, path: "/v1/{id}" }`; `custom { kind, path }` gives `method: <kind>` |
| `message M { … }`, nested `message N` | `components.messages["pkg.M"]`, `["pkg.M.N"]` |
| `int64 id = 1;` | `properties.id = { number: 1, type: integer, protoType: int64 }` |
| `repeated T x = n;` | `{ number, type: array, items: <T> }` |
| `map<K, V> x = n;` | `{ number, type: object, propertyNames: <K>, additionalProperties: <V> }`; the `*Entry` message of a descriptor is folded back and never emitted |
| message- or enum-typed field | `{ number, $ref: "#/components/messages/pkg.T" }` or `…/enums/pkg.E` |
| proto2 / proto3 `optional`, editions `EXPLICIT` | `presence: explicit` (rule P) |
| proto2 `required`, editions `LEGACY_REQUIRED` | `presence: required` |
| `oneof k { … }` | members carry `oneof: k`; `oneofs.k = { description?, deprecation?, options? }`; synthetic oneofs are hidden |
| `[json_name = "x"]` | `jsonName: x` when it differs from the default (rule J) |
| `[default = 1.5]` | `default: 1.5` (proto2 and editions) |
| `[deprecated = true]` | `deprecation: {}` (on a file it stays under `options`) |
| `[packed = …]`, `features.repeated_field_encoding` | `packed: false` when the resolved encoding of a packable repeated field is expanded |
| `features.utf8_validation`, every proto2 `string` | `utf8Validation: false` on the string position when resolved to `NONE` |
| `features.json_format`, every proto2 message and enum | `jsonFormat: LEGACY_BEST_EFFORT` when resolved to it |
| `[jstype]`, `[ctype]`, `[lazy]`, `[debug_redact]`, `[retention]`, `[targets]`, other `features.*`, custom options | `options.<name>` |
| `optional group G = n { … }` (proto2) | field `g: { number: n, $ref: "#/components/messages/pkg.M.G", delimited: true }` and the component `pkg.M.G`; the field name is the lower-cased group name |
| editions `features.message_encoding = DELIMITED` | `delimited: true` |
| `reserved 5, 7 to 9; reserved "old";` | `reserved: { numbers: [[5, 5], [7, 9]], names: [old] }` |
| `extensions 100 to 199;` | `extensions: [[100, 199]]`; `[declaration = …]` under `options.extension_declarations`, other range options in `extensionOptions` |
| `extend M { T x = n; }` at top level or inside message `S` | `components.extensions["pkg.x"]` or `["pkg.S.x"] = { extendee: "pkg.M", number: n, … }` |
| `enum E { A = 0; B = 1 [deprecated = true]; }` | `components.enums["pkg.E"] = { type: string, values: { A: { number: 0 }, B: { number: 1, deprecation: {} } } }` |
| `option allow_alias = true;` | `options.allow_alias: true` on the enum |
| proto2 enum, editions `enum_type = CLOSED` | `closed: true` |
| edition 2024 `export` / `local` | `options.visibility: export` / `local`; the default visibility writes nothing |
| well-known types | `$ref` to `components.messages["google.protobuf.*"]`, emitted when referenced |
| comments | `description` on every element |

An unknown edition is written verbatim in `syntax`, reported, and resolved with the defaults of the newest known edition. An unknown `syntax` (such as `proto4`) is an error and reads as proto2.

### 3.4 Scalar mapping

| proto | `type` | `protoType` |
| --- | --- | --- |
| `int32`, `sint32`, `sfixed32`, `uint32`, `fixed32` | `integer` | the same name |
| `int64`, `sint64`, `sfixed64`, `uint64`, `fixed64` | `integer` | the same name |
| `float`, `double` | `number` | the same name |
| `bool` | `boolean` | `bool` |
| `string` | `string` | `string` |
| `bytes` | `string` | `bytes` |

`protoType` is present at every scalar position, so a consumer never infers it from `type`. A renderer that wants ProtoJSON types maps them itself (64-bit integers are strings in ProtoJSON).

### 3.5 Identity, ordering and omission rules

**Keys.** Component keys are fully qualified names; nested types use dots (`pkg.Outer.Inner`). Extension keys are the fully qualified extension name (`pkg.name`, or `pkg.Outer.name` for an `extend` inside `Outer`). Methods are keyed by name within their service; fields, enum values and oneofs within their container. A dotted key does not imply nesting — `package a; message B {}` and `package a.B; message D {}` give the unrelated keys `a.B` and `a.B.D` — so consumers MUST NOT derive parents from key prefixes.

**Order.** `properties`, `values`, `methods` and `oneofs` keep declaration order. `files` are in topological order: entry files sorted by path, each visited depth-first with its imports first (the order of a buf image). `components.*` follow that file order, then declaration order. `reserved.numbers` and `extensions` are sorted by start and merged when adjacent or overlapping (`reserved 5, 6, 7 to 9` gives `[[5, 9]]`); `reserved.names` are sorted. `imports` keep source order.

**Rule P (presence).** `presence: required` is written on every singular field with a `required` label or a resolved `LEGACY_REQUIRED`. `presence: explicit` is written only on singular scalar and enum fields outside oneofs that have explicit presence: proto2 `optional`, proto3 `optional`, editions `EXPLICIT` (the editions default), and every extension. Message-typed fields always have presence and carry no `explicit`; oneof members, repeated and map fields carry no `presence`. So `string s = 1;` → `optional string s = 1;` adds the key, and `Foo f = 1;` → `optional Foo f = 1;` changes nothing.

**Rule J (json_name).** `jsonName` is written only when an explicit `json_name` differs from protoc's default: for each character of the field name, `_` sets a flag and is dropped, the next character is upper-cased when the flag is set, every other character is copied (`foo_bar` → `fooBar`, `foo_1bar` → `foo1bar`, `_foo` → `Foo`, `foo__bar` → `fooBar`). Descriptor sets always carry `json_name`; the producer recomputes the default and omits equal values.

**Rule D (defaults).** An option equal to its protobuf default is not written (see the table in [§3.7](#_3-7-options)). `map_entry`, `proto3_optional` and synthetic oneofs never appear. `features.*` are written as declared, not resolved, with two exceptions:

1. The lifted features `field_presence`, `enum_type` and `message_encoding` are removed from `options.features` of the field or enum they are declared on, because `presence`, `closed` and `delimited` carry them; declared on a file or message, they only set an inherited default and stay under that element's `options.features`.
2. The resolved features are written as keywords against a fixed baseline — packed, `VERIFY`, `ALLOW`, the proto3 and editions defaults — whatever the syntax: `packed: false`, `utf8Validation: false` and `jsonFormat`. proto2 therefore gives `packed: false` on repeated scalars without `[packed = true]`, `utf8Validation: false` on every string and `jsonFormat: LEGACY_BEST_EFFORT` on every message and enum; proto3 gives nothing. `packed`, `features.repeated_field_encoding`, `features.utf8_validation` and `features.json_format` never appear under `options`.

All keywords are computed from the resolved feature: field, oneof, message, enclosing messages, file, then the edition default from `descriptor.proto`.

**Absent means default.** Absent `presence` means implicit presence, absent `closed` means open, absent `stream` means unary, absent `packed` / `utf8Validation` / `jsonFormat` mean packed / `VERIFY` / `ALLOW`.

### 3.6 Canonical values

Default values, option values, bounds and the items of `enum`, `const` and `examples` use one representation per value:

| Value | Representation |
| --- | --- |
| 32-bit integers, enum numbers, field numbers | JSON number |
| 64-bit integers (`int64`, `uint64`, `sint64`, `fixed64`, `sfixed64`) | decimal string: `"9007199254740993"` |
| finite `float` and `double` | JSON number, the shortest representation that round-trips; `float` values are narrowed to 32 bits (`0.1` stays `0.1`) |
| non-finite numbers | `"Infinity"`, `"-Infinity"`, `"NaN"` |
| negative zero | `"-0"` |
| `bool` | JSON boolean |
| `string` | JSON string, escapes decoded |
| `bytes` | base64 (standard alphabet, padded): `"\x00\xFFok"` → `AP9vaw==` |
| enum values | the value name: `default: GREEN` |
| message-typed option values | an object with the field names of the message (snake_case, as declared) |
| `google.protobuf.Any` option values | `{ "@type": url, …payload }`, well-known payloads in their ProtoJSON form |
| repeated option values | an array, also with one element |

Values of well-known types inside options (protovalidate's `duration.gte`, a `Timestamp` field of a custom option) are written as messages (`{ seconds: "60" }`), not in ProtoJSON's string forms. Zero values of implicit-presence fields inside option messages are dropped, as on the wire. A value that does not convert for its type is reported and dropped.

### 3.7 Options

**Keys.** Built-in options use their descriptor field name (`java_package`, `jstype`, `allow_alias`, `features`). Custom options use the fully qualified extension name without parentheses (`buf.validate.field`, `acme.options.audit`). Sub-keys of message values are the field names of that message as declared (`min_len`, not `minLen`), in the declaration order of the message, with extension keys (fully qualified, without brackets) after the regular fields.

**Values.** Options are typed per [§3.6](#_3-6-canonical-values) when their definition is known: built-in, bundled, or present in the input. An option without a definition is kept as its source text under the key as written and reported; nothing is lifted from it. A field that a known option message does not have is kept raw and reported, and the rest of the option is still typed.

**Lifted options** are removed from `options`: `deprecated`, `json_name`, `default`, `idempotency_level`, `google.api.http`, and the convention options of [§3.8](#_3-8-annotation-layer), in full or in part. The parts that are not lifted (CEL rules, `ignore`, message rules, …) stay under the same key with only those sub-keys.

**Options equal to their default are not written:**

| Scope | Omitted when equal to |
| --- | --- |
| any element | `deprecated = false` |
| field | `jstype = JS_NORMAL`, `ctype = STRING`, `lazy = false`, `unverified_lazy = false`, `weak = false`, `debug_redact = false`, `retention = RETENTION_UNKNOWN`, `targets = []` |
| enum | `allow_alias = false` |
| message | `message_set_wire_format = false`, `no_standard_descriptor_accessor = false`, `map_entry` (always) |
| method | `idempotency_level = IDEMPOTENCY_UNKNOWN` |
| file | `java_multiple_files = false`, `java_generic_services = false`, `cc_generic_services = false`, `py_generic_services = false`, `optimize_for = SPEED`, `cc_enable_arenas = true` |
| every element | `packed`, `features.repeated_field_encoding`, `features.utf8_validation`, `features.json_format` (always: they are resolved keywords) |

**`x-` keys.** `x-default` and `x-annotation-conflicts` are the only `x-` keys; they live on the element, not under `options`.

### 3.8 Annotation layer

The producers, not the consumers, interpret annotations. Comment tags, AIP prefixes and convention options feed the same keywords, with the precedence **built-in option → `google.api.*` → `buf.validate` → `validate.rules` → `openapiv2_*` → comment tags and AIP prefixes**. When two sources set a keyword to different values, the higher one wins and an Annotation Conflict is appended to the element's `x-annotation-conflicts`; equal values are not a conflict. The [Annotations guide](/guide/annotations) lists every tag, prefix and option.

**Comments.** Comments are attached as buf attaches them (protoc agrees except in rare block-comment layouts): consecutive `//` lines, or one `/* */` block, that end on the line directly above an element are its **leading** comment; a comment that starts after the element's last token on the same line, or the first comment group on the next lines when another group, a closing `}` or a blank line follows it, is its **trailing** comment; every other comment is **detached** and ignored, except the file header. Comment markers, the leading `*` of block comments and the common indentation are removed. The description is the leading comment followed by the trailing comment, without tag lines and prefixes, normalized: runs of horizontal whitespace become one space, trailing whitespace is removed, blank lines are kept as one empty line, line breaks are kept.

**Comment tags.** One per line, a case-insensitive known name after `@`, an optional colon, and the rest of the line as the value. Tag lines are removed from the description; an invalid known tag is removed too and reported. Any other `@word` stays in the description.

**AIP prefixes.** At the start of the first line of the description, with exact casing: `Required.` → `required: true`, `Output only.` → `readOnly`, `Input only.` → `writeOnly`, `Immutable.` → `immutable`, `Identifier.` → `IDENTIFIER` in `options["google.api.field_behavior"]`, `Optional.` → nothing. On every element kind, a first line `Deprecated: <reason>` sets `deprecation.reason`. Prefixes are removed from the description.

**Requiredness.** `required: true` is annotation-level requiredness; wire-level requiredness is `presence: required` and never sets the keyword. Messages have no `required` array.

**Lifting requires the definition.** A convention option is lifted only when its definition is known; a rule family that does not fit the position stays raw and is reported.

## 4. Building documents

### 4.1 Inputs, imports and emission

A producer reads a set of files — `.proto` texts keyed by import path, or the files of a `FileDescriptorSet` — of which some are **entry files**. Imports resolve from the input first, then from the producer's bundle. A file supplied in the input is a **user file**, even under a path the bundle also has; a file resolved from the bundle is a **bundled file**.

Entry files are always emitted in full. The emission mode chooses what is emitted of imported files:

| Mode | Imported user files | Imported bundled files |
| --- | --- | --- |
| `user` (default) | in full, when reachable through imports of any kind | the declarations referenced by emitted ones |
| `referenced` | the declarations referenced by emitted ones | the declarations referenced by emitted ones |
| `all` | in full | in full |

Referenced declarations are followed transitively through field, map value and method types (not through the extendees of extensions). A bundled file that is not an entry file is marked `bundled: true` in every mode and has no header `description`. The mode is not recorded in the document: documents built in different modes are not comparable.

A producer MUST give the same document for the same files from `.proto` text and from a descriptor set with source info, in every mode.

### 4.2 Build results and issues

A build returns the document, its source map ([§5](#_5-source-map)) and a list of **issues**. A producer MUST NOT fail on invalid input: it reports an issue and emits the most complete document the input allows. An issue has a `code`, a `message`, and when known the `file`, the `location` and the `pointer` of the document node concerned.

| Code | Reported for |
| --- | --- |
| `syntax` | A file that does not parse. |
| `missing-import` | An import not found. |
| `unresolved-type`, `unresolved-extendee` | A type or extendee that does not resolve, or resolves to a name of the wrong kind or not visible from the file. |
| `unknown-option`, `invalid-option` | An option without a definition; an option value that does not fit its definition. |
| `invalid-number`, `duplicate-number`, `duplicate-name`, `reserved-conflict` | Numbering and naming errors. |
| `annotation-conflict`, `invalid-tag` | Disagreeing annotation sources; an invalid comment tag. |
| `unsupported` | Input this version cannot handle (an unknown edition, an undecodable binary set). |
| `no-source-info` | A descriptor-set file without source info. |
| `invalid-definition` | A broken syntax or edition rule. |

The [Diagnostics guide](/guide/diagnostics) describes each code.

## 5. Source map

A source map is an object from JSON pointers of the document to locations `{ file, start, end }`, with zero-based `line` and `column` (UTF-16 code units, a tab advancing to the next multiple of 4) and an exclusive `end`. Both producers MUST give the same pointers and spans for the same construct.

| Pointer | Span |
| --- | --- |
| `#/files/<path>` | the whole file |
| `#/files/<path>/syntax`, `…/package`, `…/imports/<i>`, `…/options/<name>` | the statement |
| services, methods, messages, enums | the declaration, from the keyword to the closing `}` or `;` |
| `…/request`, `…/response`; `…/request/stream`, `…/response/stream` | the type name; the `stream` keyword |
| fields, enum values, extensions | the declaration |
| `…/number`, `…/type`, `…/jsonName`, `…/default` | the token or option |
| `…/presence` | the label when written, else the field |
| `…/oneofs/<k>` | the `oneof` block |
| `…/reserved`, `…/extensions` | the first `reserved` / `extensions` statement |
| `…/reserved/numbers/<i>`, `…/reserved/names/<i>`, `…/extensions/<i>` | the written range or name that starts the interval |
| `…/extensionOptions/<i>` | the `extensions` statement of the range |
| `…/options/<name>`, `…/deprecation`, `…/idempotency`, `…/http` | the option statement |
| lifted annotation keywords | the option statement they come from, or the line of the comment tag or prefix |
| `packed`, `utf8Validation`, `jsonFormat` | the option that sets them on the element itself; inherited values have no entry |
| `…/extendee` | the extendee name of the `extend` block |

A consumer locates any other node by its nearest ancestor with an entry. See [Source maps](/guide/source-maps).

## 6. Printing

A printer turns a document into `.proto` files: one per `files` entry not marked `bundled`, with elements placed by their `file` key and nested types re-nested by their keys. Imports are the written list; one is added only when a referenced type or option is not visible through it.

Keywords print in the spelling of the file's syntax: `presence` as labels or `features.field_presence`, `delimited` as a group or `features.message_encoding`, resolved features as `[packed = …]` or `features.*`, canonical values as protobuf literals. Lifted annotation keywords print as the convention option they can come from when the file imports its definition, otherwise as a comment tag or AIP prefix; `deprecation.reason` prints as a first comment line `Deprecated: <reason>`.

**Round trip.** Building the printed files with the same options MUST give the same document, except for `x-annotation-conflicts` (after printing, one source is left). For the default mode the printed files alone suffice, since bundled files resolve from the bundle. A document without `files` prints with the syntax inferred from its content and the package from the common prefix of its keys.

## 7. Relation to JSON Schema

A message is a JSON-Schema-shaped object so that JSON Schema tooling and rules can be reused for `type`, `properties`, `items`, `additionalProperties`, `propertyNames`, `enum`, `const`, `default`, `examples`, bounds, lengths, `pattern`, `format`, `readOnly`, `writeOnly`, `title` and `description`. There are three deliberate departures:

1. **A `$ref` with siblings is a nominal reference.** `{ $ref, number, oneof, description }` means "a field of that type with these attributes", never a schema to merge with the target as in JSON Schema 2019-09. Consumers MUST NOT inline or `allOf`-merge it.
2. **protobuf keywords** — `number`, `protoType`, `presence`, `oneof`, `oneofs`, `jsonName`, `delimited`, `packed`, `utf8Validation`, `jsonFormat`, `reserved`, `extensions`, `extensionOptions`, `extendee`, `values`, `closed`, `immutable`, `deprecation`, `options`, `file` — are not JSON Schema, and generic JSON Schema code MUST treat them as opaque.
3. **Requiredness is a field keyword.** `required: true` on a field replaces JSON Schema's `required` array on the object; generic JSON Schema code MUST treat the boolean as opaque.

A renderer that needs strict JSON Schema can project a document: rebuild each message's `required` array from its fields with `required: true` (in declaration order), drop the protobuf keywords, wrap `$ref` siblings in `allOf`, map 64-bit integers to `type: string` and `google.protobuf.Timestamp` to `format: date-time`, and so on.

## 8. Versioning

`protoapi` is `"0.1"` for every document of this version of the format. Additive changes — new optional keywords — keep the version; incompatible changes increment it. Consumers SHOULD accept every `0.x` document and ignore keys they do not know.
